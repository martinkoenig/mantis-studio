## 1. Scope and chosen extension points

The concrete candidate is **A: one complete ordered outcome table carried by an existing Tensor Packet**, with a new derived artifact meaning. The operation intersects one source camera ray with one explicitly declared line plane in the existing calibrated rig frame. It estimates no physical plane and opens no device. B, compact PointCloud plus complete linked rejection ledger, is deferred: it needs reviewed empty-cloud and atomic/multi-output publication rules. There is no second prototype or A/B runtime mode.

Reuse `SemanticNodeInstance::process` (one LaserObservation input, one SemanticPublished output), `data::Packet`, `schema::tensor` version1, Attribute/BufferView, generic Store begin/append/finalize/readback, and existing immutable calibration loaders [S9,S12–S14]. The internal factory resolves and owns its exact inputs before execution, like the accepted explicitly configured ALG02 node; this is not arbitrary Plugin SDK parameter dispatch. The first version is artifact-scoped: one finalized observation reference per instance/invocation, with canonical input bytes checked against that artifact. Repeated execution may use the same bound source; a different observation requires a different explicit binding. No new global semantic variant, Packet field, ABI, protocol, service, active-calibration registry or X1 core meaning is introduced.

The proposed names `org.mantis.Alg03DeclaredPlane`, `org.mantis.Alg03Policy`, `org.mantis.Alg03Result` are **new artifact schema1 meanings under review**, not existing accepted schemas. Each contains exactly one generic Tensor1 Packet (the extensible Packet/attributes route, not an assumption that the convenience data::Tensor single-values view reads this table). Plane/policy packets have exactly `org.mantis.alg03.document`, u8[K], byte stride[1], unit `utf8-json`, 1≤K≤262144; no other attributes/children. Their headers use neutral sequence/time/sync, empty calibration id/revision0/schema1, spatial::world and empty metadata, as in existing calibration-document neutral headers. Plane coordinates live in payload.frame, not that neutral envelope. Result packets have a manifest plus the columns below. Store's calibration-revision API whitelists the four M4 types; these new types use ordinary Store::begin instead. Their ContentReference revision is fixed1: identity/version is artifact ID + artifact schema1 + exact hash + snapshot revision1. Changing content creates a new artifact/ID; there is no plane/policy logical-series allocator or mutable “current plane”. Camera/rig logical calibration revisions retain their existing meanings.

This fits ADR041's separate future laser geometry and existing arbitrary generic artifact/attribute seams [S2]. If independent review finds a genuine accepted-architecture/ABI change, a new ADR with compatibility/migration analysis is required before implementation; it must not be hidden in a new payload name. No such ABI change is proposed here.

## 2. Exact envelope, references and input binding

All new JSON documents use canonical UTF-8: sorted unique object keys, no whitespace, finite shortest round-trip binary64 numbers, exact-range unsigned integers, string enums, every named field required, null only where declared, unknown fields/enums/versions rejected. Arrays retain canonical order. Root fields are exactly `kind` (artifact type name), `schema_version` (u32,1), `payload`. No self artifact ID/hash, wall clock, random processing ID or unversioned parameter map is inside canonical bytes. JSON is an internal artifact codec, not a new public JSON service.

Reuse these typed projections: Id=`{value:string}` (nonempty,≤256 bytes); Hash=`{algorithm:string,hex:string}`; DataTypeId=`{name:string,version:u32}`; calibration Reference=`{id:Id,schema_version:u32,revision:u64}`. ContentReference is exactly `{id:Id,type:DataTypeId,hash:Evidence<Hash>,revision:u64}`. Evidence is `{presence:"unknown"}`, `{presence:"unavailable"}`, or `{presence:"established",value:T}`; no value in the first two. ExactCalibrationReference is `{calibration:Reference,content:Evidence<ContentReference>}`. CoordinateFrame is `{id:Id,name:string}`. Namespaced IDs/strings retain existing limits; no ordinal means identity. SemanticId<T> projects as `{id:Id}`, SemanticSequence<T> as `{value:u64}`, and SemanticVersion as `{major:u32,minor:u32,patch:u32}`. StreamIdentity, SourceFrameKey, ObservationKey, DatasetCamera and ImplementationIdentity retain exactly the field names/types in the cited headers, recursively using these projections. This adapts existing fields without changing their wire/ABI encoding [S10]. Hash equality is byte-consistency evidence, not physical authenticity.

Every **artifact-backed processing** camera/rig/plane/policy/observation reference requires established content and hash, exact supported type/schema, FINALIZED descriptor, matching Store hash and logical revision where applicable. ContentReference and established hash presence alone do not imply a Store artifact: reference meaning is determined by the specific accepted field/producer contract, before graph traversal or Store lookup. The selected camera/rig geometry is validated through the existing typed M4 graph, including final mono intrinsics, dataset/target documents and required reference-descriptor checks, not ID strings alone [S1,S9]. This does not recursively require the acquisition RAW/dark objects referenced by the source observation. Camera/Rig schema1 are supported by the existing loaders at A. Schema2 is an accepted ADR044 direction, but those numerical artifact loaders are not supplied at A: refuse it as incompatible, never parse it as schema1. Future schema2 support needs its exact typed adapter/qualification; this preserves rather than contradicts ADR044 [S7].

The invocation binding has exactly: `observation` (ContentReference, LaserObservation1, revision1), `camera` and `rig` (ExactCalibrationReference), `plane` and `policy` (ContentReference to new schema1 types/revision1), and `calibration_selection` (`recorded_effective` or `explicit_processing`). These are immutable internal factory inputs, not new DAG ports. Resolving the input artifact and graph is cancellable bounded downstream work; no acquisition-thread lookup occurs.

- `recorded_effective`: the source's established rig content must equal selected rig exactly. Select the camera by the plane applicability binding and that rig's camera graph; any established source camera calibration must agree with that captured graph. An unknown source camera ref stays unknown in provenance even when its effective camera is resolved through the rig graph.
- `explicit_processing`: caller deliberately supplies selected camera/rig and matching plane even if different from capture-time geometry or capture-time content is unresolved. This mode is recorded; it cannot silently fall back from recorded_effective. Source identities/dimensions/frames must still match the supplied applicability binding. Known historical contradictions/corrupt hashes are not repaired by rebinding.
- Preserve the source's `camera_calibration`, `rig_calibration`, `original_calibration` Evidence values byte-semantically, including unknown/unavailable content; do not invent original artifact references. Historical capture graph and processing graph are separate. Active metadata is never read during processing/replay [S1,S8].

**Processing dependencies versus historical lineage.** ALG03 consumes the accepted observation's coordinates, not the images/configuration that produced them. The following classification is by use, not merely by ContentReference type or presence in an artifact's Provenance.inputs:

In recorded_effective mode the chosen effective rig must still match the selected, locally validated processing rig; explicit_processing does not relabel history |

The source observation's existing Provenance.inputs may contain historical RAW/dark IDs even when no local Store rows exist. Do not blindly traverse that list, remove those IDs, rewrite the observation, fabricate FINALIZED rows, or append historical ancestors to the result's direct processing dependencies. Existing bounded known-project input type/state/hash checks and explicitly supplied identity evidence remain authoritative when available; missing historical storage alone is not inconsistency. No result claims those unexamined source pixels/lineage were locally verified. An observation-only host with the bound observation and valid selected geometry is in scope, consistent with ADR031 decision8; normal reconstruction does not require original acquisition RAW transport [S2,S19].

This preserves, rather than weakens, M4 geometry validation: its current loaders read selected camera/rig/dataset/target documents and require finalized descriptor/hash matches for calibration-dataset RAW references. A normal persisted ALG02 observation must remain admissible when no such Store row exists. This is semantic classification of the accepted producer, not a failed-lookup fallback or blanket exemption for arbitrary missing artifacts. The observation and selected processing geometry retain their required artifact-backed resolution rules; source acquisition RAW/dark references retain historical identity without mandatory resolution, as classified above. The source observation reference preserves the opaque values without changing ALG02 persistence or requiring a new parameter-artifact contract.

## 3. Mathematics, frames, inversion and bounds

Source_pixel is stored f32[N,2], widened exactly to f64: u right, v down, origin at center of original pixel(0,0). No half-pixel addition or second application of context.preprocessing.original_from_processed. Preserve that transform/reference. Require finite coordinates and `0≤u≤width-1`, `0≤v≤height-1`; no clamping/extrapolation. This is ALG03's conservative domain, not a changed generic observation validity rule.

Use exact final `PinholeBrown5` fx,fy,cx,cy,k1,k2,p1,p2,k3 from the selected camera/rig graph; finite positive focal lengths, zero skew and no rational/fisheye/thin-prism fallback. fx/fy must be in[1e-12,1e12] for this arithmetic profile. Camera optical axes are +X right,+Y down,+Z forward; M4 rig origin is the calibrated midpoint and axes are calibrated LEFT→RIGHT,+forward orthogonalized to it,+cross product. Use actual frame IDs AND names, not X1 constants. `T_rig_from_camera=[R,o]` is row-major, p_rig=R p_camera+o, mm; angles rad. Validate M4 proper rotation/composition and exact optical/rig frames [S4–S6].

With r²=x²+y², A=1+k1 r²+k2 r⁴+k3 r⁶ and B=k1+2k2 r²+3k3 r⁴, forward Brown5 is:

`xd=x A+2p1xy+p2(r²+2x²)`; `yd=y A+p1(r²+2y²)+2p2xy`.

Invert at `((u-cx)/fx,(v-cy)/fy)`. The normalized Jacobian is symmetric: diagonals A+2x²B+2p1y+6p2x and A+2y²B+6p1y+2p2x; off-diagonals 2xyB+2p1x+2p2y. Certify the entire D, not just the converged point. Let rho=a²+b², E_rad=|k1|rho+|k2|rho²+|k3|rho³, B_max=|k1|+2|k2|rho+3|k3|rho², and

`E_tan=max(2|p1|b+6|p2|a+2|p1|a+2|p2|b, 6|p1|b+2|p2|a+2|p1|a+2|p2|b)`.

A conservative `||J-I||₂≤E=E_rad+2rho B_max+E_tan` gives gamma=1-E. Evaluate the bound outward (or exactly for binary64 input rationals); require certified gamma≥0.5. This is sufficient strong monotonicity/injectivity, not necessary for every physically usable lens. Failure refuses this model/domain, without changing calibration bytes or silently choosing a different D/model.

Start Newton at(0,0). At each iteration use the analytic 2×2 J and first trial alpha=2^-j within D with strictly decreasing normalized L2 forward residual. If none of21 trials succeeds, reject inverse_failure. No search beyond100 iterations. A residual≤1e-9px is necessary, not sufficient: compute an outward normalized residual bound r against the exact stored input/model. For the nominal estimate, delta=r/gamma bounds inverse displacement. Require its closed delta ball inside D with strictly positive boundary margin if r>0; if exact r=0, the exact root may be on D's boundary. Strong monotonicity and the inward ball condition certify root existence/uniqueness; otherwise reject inverse_uncertified. Retain residual/delta. NaN/Inf, determinant/normalization failure, nonprogress or cap exhaustion is explicit rejection.

Set h=(x,y,1), w=h/||h||, v=R w, s=n·o+d, q=n·v. Intersect `tau=-s/q`, `p=o+tau v`; optical depth is `z_camera=tau*w_z`. Tau has mm units in camera-unit-ray parameterization (Euclidean ray distance for an exact rigid R); no direction renormalization or coefficient rewriting is hidden. Conditioning uses `c=|q|/(||n||||v||)` and kappa=1/c. Both vector norms must be finite/nonzero. q=0 is parallel; coplanar q=s=0 is not a unique point. Proven exact s=0 is camera_on_plane; a zero-containing s enclosure without that proof is numeric_guard. Similarly, proven q=0 is parallel, whereas a zero-containing q enclosure without that proof is numeric_guard. Reject c below the policy floor, tau≤0, z≤0, or depth/rig-position limits; uncertain sign/boundary tests are numeric_guard. camera_on_positive_side requires s>0,q<0; two_sided makes no plane-side claim. Backside means only this declared side, not reflecting-object backfaces or a measured emission volume. Reversing n,d with a one-sided rule changes declared meaning and must create a new plane artifact.

### Arithmetic, quantization and declared uncertainty

Interpret stored binary64 model/transform/plane values and source f32 values exactly for the reference calculation. No fast-math/reassociation or hidden model/backend fallback. The implementation must conservatively enclose every polynomial, residual, normalization, dot/division and transform operation, including rounding and inverse delta. Propagate the certified inverse ball through h,w,v,s,q,tau,p with outward intervals; refuse a q interval containing0. Require entire resulting depth/position intervals within policy bounds and certified c lower bound≥floor. A threshold-straddling enclosure is numeric_guard rather than an arbitrary accept. Output nominal p plus the outward L2 radius of its position enclosure; reject if radius exceeds max_numeric_error_mm. This handles floating-point error, not physical truth. Equivalent exact-rational/high-precision certification is allowed if it proves the same enclosure and honors the finite work caps; implementation evidence must name its arithmetic policy.

Source quantization is separate: nominal math uses the exact stored f32 pair. The potential pre-rounding source lies in its round-to-nearest half-ULP cell (use the larger adjacent spacing). If the whole cell admits the same bounded-domain/root/denominator proof, propagate it to a separate source_quantization_bound_mm. Otherwise that diagnostic is unavailable; never subtract it from arithmetic error or call it localization accuracy. Source curvature/confidence and M4 residual RMS are not physical uncertainties.

Declared model bounds are also separate. With origin/direction bounds eo,ev from policy and normal/offset bounds en,ed from plane, use `es=||n||eo+||o||en+en*eo+ed`, `eq=||n||ev+||v||en+en*ev`, `dt=(es+|tau|eq)/(|q|-eq)` for eq<|q|, and `model_bound=eo+|tau|ev+dt*(||v||+ev)`, all conservatively rounded. The bound covers the declared parameter model only, not unmodeled optical effects. Null bounds mean unknown, not zero. numeric_only may accept with model diagnostic unavailable/unbounded; require_declared_bound rejects missing/unbounded or above its declared allowance. No covariance or measured mm/µm scanner accuracy is inferred. Source/result origin and validity scope remain explicit.

### Ordered rejection and refusal rules

Bits0..13 of reason_bits are respectively: `producer_rejected`, `ambiguous`, `unresolved_attribution`, `line_mismatch`, `image_fov`, `inverse_failure`, `inverse_uncertified`, `parallel`, `camera_on_plane`, `near_parallel`, `backside`, `behind_camera`, `depth_or_position_domain`, `numeric_guard`; bit14 is `declared_bound_unavailable_or_exceeded`. Other result bits are0. Primary reason is the lowest set bit; no duplicate primary column.
