# v0.2 acquisition architecture gap review

Baseline reviewed: `cbb698a`, Architecture v1 (read in full). The existing
daemon, services, typed pipeline, host buffers, plugin loader and artifact store
remain the implementation. This document describes the chosen extensions;
validation.md tracks evidence, not this design document.

## Current behavior and concrete gaps

* `MantisDeviceV1.describe/create` describes one static device and cannot select
  a discovered instance. The C++ Descriptor already has children, but the C ABI
  cannot convey them. Discovery currently happens at runtime construction.
* `FrameSet` exists as a domain value, but `Published` is a flat Packet. The v1
  packet ABI loses receive time, sync information and metadata. It cannot carry
  independent native sequences/clocks/calibrations for constituent images.
* Session sleeps 33 ms between calls to every stream. That makes a requested
  120 Hz source impossible, and sequential independent streams do not establish
  a paired observation. Pairing belongs to the composite acquisition plugin.
* The lossless queue is bounded but its counters describe dequeue, not completed
  writes. There is no independent latest-only image preview or saturation deadline.
* Store::append creates, serializes, synchronizes, hashes, journals, renames and
  indexes a file for every packet. At 1280×800×2×120 RAW8 this is 245,760,000
  payload bytes/s (245.76 MB/s, 234.375 MiB/s), before overhead. Per-frame file
  and SQLite durability cannot be the recording design.
* Replay processes frame zero only. Full sequential source replay and verification
  must be generic storage/runtime facilities, without storage parsing in algorithms.

## Chosen extensions

1. Query a new generic acquisition interface using the existing plugin root ABI.
   Enumerate descriptors with stable IDs, parent IDs, capabilities and metadata;
   open a selected parent; emit explicit FrameSets with fully specified image
   headers. Preserve all v1 structure layouts and Virtual Scanner behavior.
2. Extend Packet with immutable image children for FrameSet. Add a versioned
   packet encoding while retaining the MANTIS01 reader/writer for old packets.
   Native image buffers keep host allocator ownership across ABI calls.
3. A Linux-only `org.mantis.x1` plugin owns media graph traversal, V4L2 ioctls,
   profiles, camera lifecycle and deterministic pairing. A narrow backend seam
   supplies deterministic discovery and frame events in tests. No Linux headers
   or product types enter foundation libraries.
4. Start with V4L2 MMAP and one explicit acquisition copy into host-owned Mantis
   buffers before QBUF. External-buffer/DMABUF ownership is deferred: pinning
   driver buffers behind slow consumers would reduce driver queue depth and
   requires a separate lifetime contract. Never label this path zero-copy.
5. Sequential RawCapture v2 segments use bounded length-prefixed records with
   integrity checks and a recoverable index. Batch SQLite updates at segment
   boundaries; synchronize segments, never each camera frame. Retain complete
   process-crash records, report corrupt records, and discard only incomplete
   tails during explicit recovery. Power-loss guarantees cover synced segments;
   unflushed OS/device caches cannot be promised durable.
6. Live and replay use Published FrameSet streams. Raw writer and latest-only
   preview have separate bounded branches. Local preview uses file references,
   never megabyte Protobuf fields. Qt conversion stays in Studio.
7. Add control fields/commands for metadata, diagnostics, preview and replay.
   Preserve protocol v1 field numbers and v0.1 clients.

## Alternatives and compatibility

Changing MantisDeviceV1 in place breaks deployed DSOs and is rejected. Using
alternating image packets loses the observation boundary and is rejected.
An X1-only core source would conceal public API gaps and is rejected. OpenCV
and libcamera are not needed for the native ioctl path. One file per frame and
SQLite pixel blobs are rejected for the sustained bandwidth target.

The project manifest and existing artifact tables remain version 1 if segments
can use the current chunk index. RawCapture schema 2 explicitly distinguishes
the new representation; old artifacts retain their reader. No silent metadata
reinterpretation or rewriting of historical pixels is permitted.

V4L2 timestamps retain driver clock/source flags. Hardware trigger configuration
is recorded separately from software timestamp delta and sequence agreement.
Neither implies measured optical exposure skew. Unavailable controls stay absent.

Q6A throughput, driver mode negotiation, media topology and physical trigger
behavior require user execution; no workstation fixture can certify them.
