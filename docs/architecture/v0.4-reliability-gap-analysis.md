## 1. Executive assessment

The inspected software has substantial direct failure-path coverage. In
particular, existing assertions establish bounded L3 admission/publication,
priority abort during blocked acquisition, immutable terminal snapshots,
byte-identical F2 retries, asynchronous TX abandonment containment, callback
admission fencing, software lease expiry, historical calibration binding and
exact hardware-free recording/replay. Repeating those same single-fault tests
under new names would add little evidence.

**No confirmed implementation correctness or safety defect was identified in
the inspected paths.** This is not a claim that uninspected code is defect-free.
The remaining HIGH-priority evidence gaps concern durable storage failures and
commit crash windows, combined recorder/transport failures, and integrated
client/shutdown/generation interleavings. Existing component containment makes
these plausible bounded failures, not demonstrated corruption or invalid
authority. MEDIUM gaps concern cancellation inside large replay scans and
sustained cross-component resource/performance qualification.

Recommend three follow-up packages: L8a-1 combined faults/durable recovery;
L8a-2 concurrency and bounded-resource qualification; L8a-3 final hardware-free
qualification. This consolidates the provisional separate concurrency and
performance packages because their missing evidence uses the same lifetime and
load harnesses. These are proposals for review, not frozen architectural
contracts or authorization to implement them in L8a-0.

Method: enumerate registered CTests; inspect their command/source registrations;
read relevant implementation control/data paths and assertion bodies; distinguish
component, in-process service and actual daemon processes; identify the narrower
invariant established; compare missing combinations against existing containment.
Searches included fault injection, cancellation, durability, session fencing,
resource accounting, retained ownership, process death and benchmark registration.
A successful historical suite alone is not a coverage argument.
The matrix contains 49 scoped invariants: 35 COVERED, 10 PARTIAL, one
NOT COVERED, two HARDWARE BLOCKED and one OUT OF SCOPE. These counts describe
this selected requirement set, not a percentage of all repository behavior.

Two composition facts constrain useful new tests. [mantisd](../../apps/mantisd/main.cpp)
lines 57–84 processes one request/response connection at a time; the Runtime
control surface is not established as an arbitrary concurrently callable API.
Competing clients therefore test dispatch ordering and interaction with existing
background workers, not a new multithreaded service contract. The shared F2
fixture completes `start()`/RUN admission before its first control bundle and
produces only that bundle plus terminal. A partial pre-admission RUN cannot
coexist with its own saturated recorder. Use the existing R1 test for that
phase; combine recorder pressure with *post-admission terminal recovery/STOP*,
or use accepted multi-publication L7a/generic fixtures for full L3 ring pressure.
Do not widen the F2 one-step subset to manufacture an unreachable scenario.

Classifications are **COVERED**, **PARTIAL**, **NOT COVERED**, **HARDWARE BLOCKED**
and **OUT OF SCOPE**. COVERED applies only to the stated bounded invariant and
listed conditions. PARTIAL does not assert a code defect. No branch/line-coverage
percentage, formal race proof, exhaustive fault search or uninspected-platform
support is claimed. UI behavior, geometric solver quality, broad network/security
qualification and future algorithms were not independently audited.

## 6. Confirmed defects versus missing evidence

No immediately actionable production defect was confirmed. Consequently this
package changes no implementation, tests, CMake, ABI or storage bytes and does
not reopen accepted protocol decisions. Findings G01–G05 below are **verification
gaps**, not diagnoses of silent corruption, unsafe output or deadlock.

Two relevant inspected limits are already explicit accepted constraints:

- [ProjectedRun](../../src/device-runtime/projected_run.cpp):145–149 joins its
  ordinary worker; [sequencer contract](projected-light-sequencer.md) requires
  finite cooperative in-process executor calls. It cannot forcibly stop arbitrary
  native plugin code. BUSY destroy/quarantine and isolated processing tests do not
  prove containment of a permanently hung in-process device plugin. Process-isolated
  device execution is a later architecture scope, not an L8a refactor proposal.
- [Store::recover](../../src/artifact-store/artifact-store.cpp):1234–1272 accepts
  RECOVERABLE only. "Idempotent recovery" in qualification must mean deterministic
  interruption/retry and unchanged rejection after FINALIZED, not a new API behavior.

The review also distinguishes actual evidence boundaries: E02's blocked-Store
append holds an unrelated synthetic append while a pending run stops; it proves
service/Store lock separation, not that a PTY-backed run's own saturated recorder
and a blocked STOP both make progress. E10's graceful shutdown and E03's post-flush
SIGKILL are not all commit-phase daemon crash tests. Those distinctions motivate
small additional tests rather than speculative production changes.
